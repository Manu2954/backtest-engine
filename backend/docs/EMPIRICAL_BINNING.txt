# EMPIRICAL BINNING - Phase 1B Implementation

## Overview

Empirical binning is a data-driven approach to validate which indicator value ranges correlate with profitable trades. Unlike Phase 1B's original plan (5 indicator-specific calculators with arbitrary thresholds like RSI < 30 = "strong"), this approach learns directly from backtest outcomes.

**Key Insight**: Instead of encoding subjective rules, let the data tell us which indicator ranges matter.

## What Problem Does This Solve?

**The Phase 1B Problem** (per senior engineer feedback):
- Arbitrary thresholds (RSI 30/70, ADX 25) are subjective curve-fitting
- 5 calculators × multiple parameters = combinatorial explosion
- No validation method - can't prove assumptions are correct
- Different assets/regimes need different thresholds
- Wastes development effort on features that may not add value

**Empirical Binning Solution**:
- Learns from actual trade outcomes (data-driven, not assumption-driven)
- Single algorithm works for any indicator (no per-indicator logic)
- Statistical validation via Spearman correlation + p-values
- Asset-agnostic - bins adapt to each strategy's behavior
- Sets up Phase 2 (robustness analysis) by identifying which indicators are predictive

## How It Works

### Step 1: Collect Trade Data

After a backtest completes with attribution enabled, each trade has:
- Entry indicator snapshot: `{"rsi_14": 28.5, "sma_50": 105.2, ...}`
- P&L: `+$250.00` or `-$120.50`

### Step 2: Bin Indicator Values

For each indicator (e.g., RSI), bin its entry values into 5 bins (quintiles):

```
Example: 100 trades with RSI from 10-90

Bin 1: RSI 10-30  (30 trades)
Bin 2: RSI 30-45  (25 trades)
Bin 3: RSI 45-60  (20 trades)
Bin 4: RSI 60-75  (15 trades)
Bin 5: RSI 75-90  (10 trades)
```

**Key Point**: Bins are NOT pre-defined. They're computed from quintiles (20th, 40th, 60th, 80th, 100th percentiles) of the actual data distribution.

### Step 3: Calculate Bin Statistics

For each bin, compute:
- **Count**: Number of trades in this bin
- **Avg P&L**: Mean P&L across trades in this bin
- **Win Rate**: Percentage of profitable trades in this bin

### Step 4: Compute Correlation

Calculate **trade-level Spearman correlation** between indicator value and P&L:
- NOT bin-level (5 data points) - statistically invalid
- Trade-level (100 data points) - statistically valid

**Spearman correlation** (rank-based, non-parametric):
- +1.0 = perfect positive correlation (higher indicator → higher P&L)
- 0.0 = no correlation (indicator doesn't predict outcomes)
- -1.0 = perfect negative correlation (higher indicator → lower P&L)

**P-value**: Statistical significance
- p < 0.05 → correlation is statistically significant
- p >= 0.05 → correlation could be random chance

### Step 5: Generate Report

Output structure:
```
{
    "rsi_14": {
        "bins": [
            {"range": [10, 30], "count": 30, "avg_pnl": 250.0, "win_rate": 0.67},
            {"range": [30, 45], "count": 25, "avg_pnl": 150.0, "win_rate": 0.60},
            {"range": [45, 60], "count": 20, "avg_pnl": -50.0, "win_rate": 0.45},
            {"range": [60, 75], "count": 15, "avg_pnl": -100.0, "win_rate": 0.40},
            {"range": [75, 90], "count": 10, "avg_pnl": -200.0, "win_rate": 0.30}
        ],
        "bin_edges": [10, 30, 45, 60, 75, 90],
        "correlation": -0.72,  # Strong negative correlation
        "p_value": 0.001,      # Highly significant
        "sample_size": 100
    },
    "sma_50": { ... },
    "summary": {
        "total_indicators": 5,
        "analyzed_indicators": 3,
        "significant_indicators": 1,  # p < 0.05
        "skipped_indicators": ["ema_cross"],  # Crossover-only
        "insufficient_data": false
    }
}
```

## Interpreting Results

### Correlation Strength

| Correlation | Interpretation |
|-------------|----------------|
| \|corr\| > 0.7 | **Strong predictor** - Indicator clearly matters, optimize around it |
| \|corr\| 0.5-0.7 | **Moderate predictor** - Indicator helps, but not sole driver |
| \|corr\| 0.3-0.5 | **Weak predictor** - Indicator has some signal, borderline useful |
| \|corr\| < 0.3 | **No predictor** - Indicator noise, consider removing |

### P-Value Significance

| P-value | Interpretation |
|---------|----------------|
| p < 0.01 | **Highly significant** - Very unlikely to be random chance |
| p < 0.05 | **Significant** - Standard statistical threshold |
| p >= 0.05 | **Not significant** - Could be random, don't trust correlation |

### Example Interpretation

**RSI with correlation = -0.72, p = 0.001**:
- **Strong negative correlation**: Lower RSI → Higher P&L
- **Highly significant**: This relationship is real, not random
- **Actionable**: This strategy profits from RSI oversold signals
- **Recommendation**: Keep RSI, optimize RSI threshold via parameter testing

**Volume with correlation = 0.15, p = 0.35**:
- **Weak correlation**: Volume barely predicts outcomes
- **Not significant**: Relationship could be random noise
- **Actionable**: Volume doesn't help this strategy
- **Recommendation**: Remove volume condition, simplifies strategy

## Requirements & Limitations

### Minimum Trade Count: 50

**Why 50 trades?**
- 5 bins (quintiles) = 10 trades per bin on average
- Need ~10 samples per bin for stable averages
- Statistical power for Spearman correlation
- Senior's recommendation: Even 50 is borderline low

**What if < 50 trades?**
- Binning report returns `None`
- User sees no binning analysis in report
- Run longer backtest or use more frequent entry signals

### Entry Snapshots Only

**Why only entry snapshots?**
- Exit indicator values are post-hoc (influenced by trade outcome)
- Entry values are pre-trade (predictive signal strength)
- Exit analysis would introduce look-ahead bias

**What about exit conditions?**
- Exit conditions are NOT binned
- Binning validates entry signal quality, not exit timing

### Crossover Conditions Skipped

**Why skip crossovers?**
- Crossover operators (CROSSES_ABOVE, CROSSES_BELOW) produce binary signals (true/false)
- Cannot bin binary values - no continuous range
- Indicator value itself MAY still be useful, but not crossover result

**Example**:
- Strategy: `EMA_20 CROSSES_ABOVE EMA_50` (entry)
- Binning: Skips `ema_20` if ONLY used in crossover
- Reason: "Did EMA cross?" is binary, but "EMA value = 105" is continuous

**Workaround** (future):
- Could bin `ema_20` VALUE even if used in crossover
- Current implementation: Conservative, skip entirely

### Data Quality

**Handles NaN values**:
- Trades with NaN indicator snapshots are filtered out
- If too many NaN trades → insufficient data

**Handles constant values**:
- If all indicator values identical (e.g., all RSI = 50) → indicator skipped
- Cannot bin a constant - no variation to analyze

**Handles skewed distributions**:
- Quintiles adapt to data distribution
- If 90% of trades have RSI > 60, bins concentrate in that range

## Usage

### Backend (Automatic)

Binning report is generated automatically when:
1. Backtest run has `enable_attribution = True`
2. Backtest completes with 50+ trades
3. Trade logs include indicator snapshots

Report appears in backtest response:
```python
{
    "report": {
        "total_return_pct": 25.5,
        "total_trades": 85,
        "attribution": { ... },  # Phase 1A confluence report
        "binning_analysis": {    # Phase 1B empirical binning
            "rsi_14": { ... },
            "summary": { ... }
        }
    }
}
```

### Programmatic Access

```python
from app.engine.report_generator import generate_binning_report

# trades: List of trade dicts with indicator_snapshot_entry
# indicators: List of indicator dicts with 'alias' key
# conditions: Optional list for crossover detection

binning_report = generate_binning_report(
    trades=trades,
    indicators=indicators,
    conditions=conditions
)

if binning_report:
    for indicator_alias, data in binning_report.items():
        if indicator_alias == "summary":
            continue

        print(f"{indicator_alias}:")
        print(f"  Correlation: {data['correlation']:.3f}")
        print(f"  P-value: {data['p_value']:.4f}")
        print(f"  Sample size: {data['sample_size']}")

        for bin in data['bins']:
            print(f"  Range {bin['range']}: {bin['count']} trades, avg P&L ${bin['avg_pnl']:.2f}")
```

## Future Enhancements

### Phase 2 Integration (Robustness Analysis)

Use binning results to:
1. **Prioritize parameters for testing**: If RSI has 0.72 correlation but SMA has 0.15, focus robustness tests on RSI period variations
2. **Weight conditions in scoring**: High-correlation indicators get higher weight in composite scores
3. **Regime detection**: Bin trades by market regime (bull/bear) to see if correlations hold across regimes

### Real-Time Scoring (Optional)

- Persist bin definitions to database after backtest
- During live trading, look up indicator value → bin → historical avg P&L
- Use as confidence score for entry signals
- **Not implemented**: Keep it simple, validate hypothesis first

### Advanced Binning

- **Multi-dimensional bins**: RSI × Volume quintiles → 25 bins
- **Adaptive bin counts**: Use Freedman-Diaconis rule instead of fixed 5 bins
- **Time-decay weighting**: Recent trades weighted higher than old trades

**Not implementing now**: These add complexity without validating core hypothesis

## Senior's Feedback Addressed

1. **"Spearman correlation on 5 bins is statistically weak"**
   - ✅ Fixed: Compute correlation on trade-level data (100+ points), not bin averages

2. **"Quintiles with small trade counts produce garbage bins"**
   - ✅ Fixed: Minimum 50 trades required (was 20 in plan)
   - ✅ Always use 5 bins (no dynamic reduction)

3. **"Crossover conditions are still unhandled"**
   - ✅ Fixed: Explicitly detect and skip crossover-only indicators
   - ✅ Add `skipped_indicators` list to summary with reason

4. **"'Strongest predictor' summary is premature"**
   - ✅ Fixed: Removed `strongest_predictor` field
   - ✅ Keep `significant_indicators` count (p < 0.05) only
