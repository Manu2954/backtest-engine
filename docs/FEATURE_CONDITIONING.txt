Feature-Based Conditional Analysis
====================================

OVERVIEW
--------
Feature conditioning finds which observable market conditions predict trade success.
Unlike regime detection (which labels markets), this provides actionable, real-time
measurable conditions for filtering trades.

KEY DIFFERENCE FROM REGIME DETECTION
------------------------------------
Regime Detection (descriptive):
  - Labels: "This was a BULL market"
  - Problem: How do you detect "BULL" in production?
  - Output: "Strategy works in BULL regimes"
  - Actionability: Low (labels are backward-looking)

Feature Conditioning (predictive):
  - Features: "vol=0.02, trend_strength=0.7"
  - Directly computable in real-time
  - Output: "Trade when vol ∈ [0.015, 0.025] AND trend_strength > 0.6"
  - Actionability: High (check features before each trade)

WHAT GETS EXTRACTED
-------------------
At each trade entry, the system extracts these features:

1. volatility
   - Rolling std of log returns (20-50 bar window)
   - Measures market turbulence
   - Range: typically 0.01-0.05 for daily crypto

2. trend_strength
   - R² from OLS regression on log prices
   - 0 = no trend, 1 = perfect trend
   - Higher R² = more reliable trend

3. trend_slope
   - Slope from same OLS regression
   - Positive = uptrend, negative = downtrend
   - Magnitude indicates trend steepness

4. price_vs_sma50
   - (price - SMA50) / SMA50
   - Measures relative position to moving average
   - Positive = above MA, negative = below MA

5. returns_autocorr
   - Lag-1 autocorrelation of returns
   - Negative = mean reversion signal
   - Positive = momentum signal

6. rsi_level (optional, if strategy uses RSI)
   - RSI value at entry
   - 0-100 scale, 30/70 traditional thresholds

7. atr_pct (optional, if strategy uses ATR)
   - ATR as percentage of price
   - Volatility normalized by price level

HOW IT WORKS
------------
1. Run full backtest → get all trades
2. For each trade, extract features at entry time
3. Bin each feature into quartiles (4 ranges)
4. Calculate win rate, avg PnL per bin
5. Identify high/low performing bins
6. Report actionable conditions

USE CASES
---------
1. Pre-trade filtering
   - Before entering trade, check current features
   - Only enter if features match winning conditions
   - Example: if vol > 0.035, skip this trade

2. Position sizing
   - Larger size when features strongly favor
   - Smaller size when features marginal

3. Strategy debugging
   - Why did strategy underperform last month?
   - Check: were features outside winning ranges?

4. Strategy improvement
   - Add feature filters to entry rules
   - Example: "RSI cross AND vol ∈ [0.015, 0.025]"

PARAMETERS
----------
lookback_window: int (default 50, range 20-100)
  - Bars used for rolling feature calculations
  - 50 bars ≈ 2 months for daily, 2 days for 1h
  - Shorter = more responsive, longer = more stable

min_trades_per_bin: int (default 10, range 5-30)
  - Minimum trades to consider a bin reliable
  - Higher = more confidence, fewer conditions found
  - Lower = more conditions, less reliable

INTERPRETATION GUIDE
--------------------
Feature Importance:
  - 1.0 = Most critical feature
  - 0.5-0.8 = Important, consider in filters
  - <0.3 = Low impact, can ignore

Win Rate Thresholds:
  - >=60% = Strong winning condition
  - 40-60% = Neutral, no edge
  - <=40% = Losing condition, avoid

Confidence Levels:
  - HIGH (>=20 trades): Trust this condition
  - MEDIUM (10-19 trades): Use with caution
  - LOW (<10 trades): Excluded from analysis

COMMON PATTERNS
---------------
Directional Strategies:
  - Usually depend on trend_slope + trend_strength
  - Example: "Trade when trend_slope > 0 AND R² > 0.7"

Mean Reversion Strategies:
  - Usually depend on returns_autocorr + price_vs_sma50
  - Example: "Trade when autocorr < -0.2 AND price_vs_sma50 < -0.05"

Volatility Strategies:
  - Usually depend on volatility + atr_pct
  - Example: "Trade when vol ∈ [0.02, 0.03]"

LIMITATIONS
-----------
1. Single-feature analysis only (not combinations)
   - Future: could add 2-feature combinations
   - Example: "vol ∈ [X,Y] AND trend_strength > Z"

2. Binning can miss non-linear patterns
   - Current: quartile bins (4 ranges)
   - Future: adaptive binning or decision trees

3. Requires sufficient trades
   - Minimum 20-40 trades for reliable results
   - More trades = more bins = finer granularity

4. Features are general-purpose
   - Not strategy-specific
   - Future: could extract strategy indicator values

COMPARISON TO OTHER ANALYSES
-----------------------------
Parameter Sensitivity:
  - Tests: "Does strategy break if I change SMA 50 → 40?"
  - Feature Conditioning: "When should I use this strategy?"

Walk-Forward:
  - Tests: "Does strategy work in different time periods?"
  - Feature Conditioning: "What conditions predict success?"

Regime Detection:
  - Tests: "How does strategy perform in BULL vs BEAR?"
  - Feature Conditioning: "What measurable features drive performance?"

EXAMPLE WORKFLOW
----------------
1. Run parameter sensitivity → "Strategy is ROBUST"
2. Run walk-forward → "Strategy consistent across windows"
3. Run feature conditioning → "Trade when trend_slope > 0.001"
4. Add filter to strategy: "Enter if (signal AND trend_slope > 0.001)"
5. Re-backtest with filter → improved metrics

REFERENCES
----------
- Based on statistical conditioning methods used by quant firms
- Alternative to regime classification (more actionable)
- Features chosen for real-time availability (no lookahead)
- Quartile binning is robust to outliers
- Feature importance via variance of win rates across bins
