FLAW 2: CROSSOVER STRENGTH MEASURES WRONG THING
------------------------------------------------

PROBLEM:
Attribution is about ENTRY conditions (bar when trade was entered), not current
bar conditions during the trade.

PHASE 1B SPEC (flawed):
- Calculate crossover strength with decay: 1 bar ago → 0.86, 3 bars ago → 0.64
- If trade entered at bar 100 (MACD crossed at bar 97)
- At bar 108 (during trade), crossover is now 11 bars old → strength ~0.20
- Trade exits at bar 110
- Attribution captures strength=0.20 (wrong - should be strength at entry)

CORRECT BEHAVIOR:
- Trade entered at bar 100
- MACD crossed at bar 97 (3 bars before entry)
- Strength at entry = 0.64 (3 bars decay)
- This strength is FIXED for attribution, regardless of exit bar
- Don't recalculate strength during trade - capture it at entry only

CURRENT PHASE 1B SPEC:
Doesn't specify WHEN strength is calculated. Implementation would likely
calculate it wrong (at current bar instead of entry bar).

FIX REQUIRED:

FLAW 4: HYBRID AVERAGING IS INCOHERENT
---------------------------------------

PROBLEM:
Averaging continuous scores (0.0-1.0 from oscillators) with binary scores
(0.0 or 1.0 from unknown indicators) produces meaningless results.

EXAMPLE:
Strategy: "RSI < 30 AND price > SMA_200"
- RSI=20 → oscillator strength = 0.33
- price > SMA → unknown indicator → binary fallback = 1.0 (condition met)
- Average = (0.33 + 1.0) / 2 = 0.665

Different strategy: "RSI < 30 AND ADX > 25"
- RSI=20 → oscillator strength = 0.33
- ADX=40 → momentum strength = 0.67
- Average = (0.33 + 0.67) / 2 = 0.50

Why is the first strategy (0.665) "stronger" when the SMA condition contributed
nothing but a binary "yes"? The scales are incompatible.

CORRECT APPROACH:
Options:
1. Exclude binary fallback conditions from average (only average known indicators)
2. Use weighted average (known indicators weight=1.0, fallback weight=0.5)
3. Convert binary to continuous: If condition met but no strength calc available → 0.5 (neutral)

FLAW 7: FORMULA IGNORES STRATEGY THRESHOLDS
--------------------------------------------

PROBLEM:
Calculator hardcodes oversold=30, but strategy might use RSI < 25 (more conservative).

CURRENT FORMULA:
strength = 1.0 - (value / 30)
RSI=24 → strength = 0.20

But for "RSI < 25" strategy, RSI=24 is MAXIMUM satisfaction (just barely met).
Should have high strength, not 0.20.

CORRECT APPROACH:
Normalize to strategy's actual threshold:
```python
threshold = float(condition.right_operand_value)  # e.g., 25
strength = 1.0 - (value / threshold)
RSI=24 with threshold=25 → strength = 0.04 (just satisfied)
RSI=10 with threshold=25 → strength = 0.60 (well into extreme)
```

Denominator should be the condition's threshold, not a hardcoded default.

#!/usr/bin/env python3
"""
Validate Phase 1B hypotheses before implementation.

Hypothesis 1: Lower RSI at entry correlates with higher win rate
Hypothesis 2: Recent MACD crossovers correlate with higher win rate
Hypothesis 3: Indicator-aware scoring predicts win rate better than confluence

If hypotheses fail, Phase 1B should not be implemented.
"""

import pandas as pd
import asyncio
from sqlalchemy import select
from app.core.database import get_session
from app.models.backtest import TradeLog, BacktestRun
from scipy.stats import chi2_contingency, spearmanr
import json

async def extract_trade_data():
    """Extract all Phase 1A trades with attribution data."""
    async with get_session() as session:
        stmt = select(TradeLog, BacktestRun).join(
            BacktestRun, TradeLog.backtest_run_id == BacktestRun.id
        ).where(
            BacktestRun.enable_attribution == True,
            TradeLog.entry_conditions_met.isnot(None)
        )

        result = await session.execute(stmt)
        trades = result.all()

    # Convert to DataFrame
    data = []
    for trade, backtest in trades:
        indicator_snapshot = json.loads(trade.indicator_snapshot_entry or '{}')
        data.append({
            'entry_date': trade.entry_date,
            'exit_date': trade.exit_date,
            'pnl_pct': trade.pnl_pct,
            'is_win': trade.pnl_pct > 0,
            'entry_signal_strength': trade.entry_signal_strength,
            'indicators': indicator_snapshot
        })

    return pd.DataFrame(data)

def analyze_rsi_hypothesis(df):
    """Test: Does lower RSI correlate with higher win rate?"""
    # Extract RSI values (find RSI columns)
    rsi_cols = [col for col in df.iloc[0]['indicators'].keys() if 'rsi' in col.lower()]

    if not rsi_cols:
        print("No RSI data found, skipping RSI hypothesis")
        return

    # Use first RSI column found
    rsi_col = rsi_cols[0]
    df['rsi_value'] = df['indicators'].apply(lambda x: x.get(rsi_col))

    # Bin RSI values
    df['rsi_bin'] = pd.cut(df['rsi_value'],
                            bins=[0, 20, 25, 28, 30, 100],
                            labels=['0-20', '20-25', '25-28', '28-30', '30+'])

    # Calculate win rate per bin
    rsi_analysis = df.groupby('rsi_bin').agg({
        'is_win': ['count', 'sum', 'mean'],
        'pnl_pct': 'mean'
    }).round(3)

    print("\n" + "="*60)
    print("RSI HYPOTHESIS VALIDATION")
    print("="*60)
    print(rsi_analysis)

    # Chi-square test
    contingency = pd.crosstab(df['rsi_bin'], df['is_win'])
    chi2, p_value, dof, expected = chi2_contingency(contingency)

    print(f"\nChi-square test: χ²={chi2:.3f}, p-value={p_value:.4f}")

    # Correlation test
    correlation, corr_p = spearmanr(df['rsi_value'].dropna(),
                                     df['is_win'])
    print(f"Spearman correlation: r={correlation:.3f}, p-value={corr_p:.4f}")

    # Verdict
    if p_value < 0.05 and correlation < -0.15:
        print("\n✅ HYPOTHESIS VALIDATED: Lower RSI predicts higher win rate")
        return True
    else:
        print("\n❌ HYPOTHESIS FAILED: No significant correlation")
        return False
