1. PERFORMANCE METRICS
================================================================================

--------------------------------------------------------------------------------
1.1 TOTAL RETURN
--------------------------------------------------------------------------------

Formula:
    Total Return (%) = ((Final Capital - Initial Capital) / Initial Capital) * 100

Example:
    Initial Capital = $10,000
    Final Capital = $15,000
    Total Return = ((15000 - 10000) / 10000) * 100 = 50%

Code Location: report_generator.py:211

Notes:
    - Expressed as a percentage
    - Includes all realized and unrealized gains/losses
    - Accounts for transaction costs (commissions, slippage)


--------------------------------------------------------------------------------
1.2 CAGR (Compound Annual Growth Rate)
--------------------------------------------------------------------------------

Formula:
    CAGR (%) = ((Final Capital / Initial Capital) ^ (1 / Years) - 1) * 100

Where:
    Years = (End Date - Start Date) / 365.25

Example:
    Initial Capital = $10,000
    Final Capital = $15,000
    Period = 2 years
    CAGR = ((15000 / 10000) ^ (1/2) - 1) * 100 = 22.47%

Code Location: report_generator.py:219-222

Notes:
    - Annualized return that accounts for compounding
    - Uses 365.25 days/year to account for leap years
    - Returns 0 if period < 1 year or initial capital = 0
    - Expressed as a percentage (not decimal)


--------------------------------------------------------------------------------
1.3 SHARPE RATIO
--------------------------------------------------------------------------------

Formula:
    Sharpe Ratio = (Mean Daily Excess Return / Std Dev of Daily Returns) * sqrt(252)

Full Formula:
    Sharpe = ((μ - Rf_daily) / σ) * √252

Where:
    μ = mean of daily percentage returns
    σ = standard deviation of daily percentage returns
    Rf_daily = daily risk-free rate = (1 + Rf_annual)^(1/252) - 1
    252 = trading days per year (annualization factor)

Example (with 5% annual risk-free rate):
    Mean daily return = 0.05% (0.0005)
    Std dev of daily returns = 1.5% (0.015)
    Annual Rf = 5% (0.05)
    Daily Rf = (1.05)^(1/252) - 1 = 0.000194 (0.0194%)
    Excess return = 0.0005 - 0.000194 = 0.000306
    Sharpe = (0.000306 / 0.015) * sqrt(252) = 0.32

Example (with 0% risk-free rate):
    Sharpe = (0.0005 / 0.015) * sqrt(252) = 0.53

Code Location: report_generator.py:250-256

API Parameter:
    risk_free_rate: float = 0.0  # Annual rate (e.g., 0.05 for 5%)

Interpretation:
    Sharpe < 0    : Negative risk-adjusted returns
    0 < Sharpe < 1: Returns don't justify the risk
    1 < Sharpe < 2: Good risk-adjusted returns
    2 < Sharpe < 3: Very good risk-adjusted returns
    Sharpe > 3    : Excellent (or possibly overfitted)

Notes:
    - Risk-free rate defaults to 0 if not specified
    - User can specify annual risk-free rate (e.g., current Treasury yield)
    - Automatically converted to daily rate internally
    - 252 trading days per year assumed


--------------------------------------------------------------------------------
1.4 MAXIMUM DRAWDOWN
--------------------------------------------------------------------------------

Formula:
    Drawdown(t) = (Equity(t) - Running Max(t)) / Running Max(t)
    Max Drawdown (%) = min(Drawdown) * 100

Where:
    Running Max(t) = max(Equity(0), Equity(1), ..., Equity(t))

Example:
    Equity peaks at $12,000, drops to $9,000
    Drawdown = (9000 - 12000) / 12000 = -25%
    Max Drawdown = -25%

Code Location: report_generator.py:87-92

Notes:
    - Always negative or zero
    - Measures worst peak-to-trough decline
    - Important for understanding downside risk
    - Expressed as a percentage


--------------------------------------------------------------------------------
1.5 LONGEST DRAWDOWN DURATION
--------------------------------------------------------------------------------

Formula:
    For each drawdown period (equity < previous peak):
        Duration = End Date - Start Date (in days)
    Longest Drawdown = max(all durations)

Code Location: report_generator.py:95-123

Notes:
    - Measures how long the strategy stayed underwater
    - Important for psychological tolerance assessment
    - Expressed in calendar days


--------------------------------------------------------------------------------
1.6 WIN RATE
--------------------------------------------------------------------------------

Formula:
    Win Rate (%) = (Number of Winning Trades / Total Trades) * 100

Where:
    Winning Trade = trade with PnL > 0

Example:
    60 winning trades out of 100 total
    Win Rate = (60 / 100) * 100 = 60%

Code Location: report_generator.py:230

Notes:
    - Does not account for size of wins/losses
    - High win rate doesn't guarantee profitability
    - Should be considered alongside avg win/loss ratio


--------------------------------------------------------------------------------
1.7 PROFIT FACTOR
--------------------------------------------------------------------------------

Formula:
    Profit Factor = Gross Profit / Gross Loss

Where:
    Gross Profit = sum of all positive PnLs
    Gross Loss = |sum of all negative PnLs|

Example:
    Total wins = $15,000
    Total losses = $10,000
    Profit Factor = 15000 / 10000 = 1.5

Code Location: report_generator.py:254-256

Interpretation:
    PF < 1.0: Losing strategy
    PF = 1.0: Break-even
    1.0 < PF < 1.5: Marginal
    1.5 < PF < 2.0: Good
    PF > 2.0: Excellent

Notes:
    - Returns 0 if no losses (edge case)
    - Simple ratio of money won to money lost


--------------------------------------------------------------------------------
1.8 AVERAGE WIN/LOSS RATIO
--------------------------------------------------------------------------------

Formula:
    Avg Win = sum(winning PnLs) / count(winning trades)
    Avg Loss = sum(losing PnLs) / count(losing trades)
    Avg Win/Loss Ratio = Avg Win / |Avg Loss|

Example:
    Avg Win = $500
    Avg Loss = -$200
    Ratio = 500 / 200 = 2.5

Code Location: report_generator.py:231-243

Edge Cases:
    - No losses: Returns 999999 (large number, not infinity)
    - No wins: Returns 0
    - No trades: Returns 0

Notes:
    - Also called "reward-to-risk ratio"
    - Combined with win rate determines profitability

2. BENCHMARK COMPARISON
================================================================================

--------------------------------------------------------------------------------
2.1 BUY-AND-HOLD EQUITY
--------------------------------------------------------------------------------

Formula:
    Equity(t) = Initial Capital * (Close(t) / Open(0))

Where:
    Open(0) = opening price on first bar
    Close(t) = closing price on bar t

Example:
    Initial Capital = $10,000
    Entry Price (Open) = $100
    Current Close = $120
    Equity = 10000 * (120 / 100) = $12,000

Code Location: report_generator.py:9-59

Notes:
    - Represents passive investment (buy and hold)
    - Uses percentage returns, not actual shares
    - Works for any price level (handles high-priced assets)
    - Calculated from ORIGINAL data (before warmup trim)


--------------------------------------------------------------------------------
2.2 ALPHA
--------------------------------------------------------------------------------

Formula:
    Alpha (%) = Strategy Return (%) - Benchmark Return (%)

Example:
    Strategy Return = 25%
    Benchmark Return = 15%
    Alpha = 25 - 15 = 10%

Code Location: report_generator.py:168

Notes:
    - Measures excess return over buy-and-hold
    - Positive alpha = strategy outperformed
    - Negative alpha = would have been better to buy and hold
    - This is "simple alpha", not Jensen's Alpha


--------------------------------------------------------------------------------
2.3 BETA
--------------------------------------------------------------------------------

Formula:
    Beta = Cov(Strategy Returns, Benchmark Returns) / Var(Benchmark Returns)

Where:
    Cov = covariance
    Var = variance

Code Location: report_generator.py:182-186

Interpretation:
    Beta = 1.0: Strategy moves with the market
    Beta > 1.0: Strategy is more volatile than market
    Beta < 1.0: Strategy is less volatile than market
    Beta < 0:   Strategy moves opposite to market

Notes:
    - Calculated on overlapping period only
    - Measures systematic risk exposure

3. TRADE EXECUTION
================================================================================

--------------------------------------------------------------------------------
3.1 FILL PRICE LOGIC
--------------------------------------------------------------------------------

Entry Fill:
    - Signal generated on bar T
    - Entry executed at OPEN of bar T+1

Exit Fill:
    - Signal generated on bar T
    - Exit executed at OPEN of bar T+1

Code Location: state_machine.py (run_backtest function)

Rationale:
    - Prevents lookahead bias
    - Simulates realistic execution (can't trade on close)
    - Signal at close -> order placed -> fills at next open

Force Close:
    - Open positions closed at last bar's close price
    - Ensures no positions carried past backtest period


--------------------------------------------------------------------------------
3.2 POSITION SIZING METHODS
--------------------------------------------------------------------------------

a) Full Capital (default)
    Shares = Available Cash / Entry Price
    Uses 100% of available capital

b) Percent Capital
    Shares = (Available Cash * Percentage) / Entry Price
    Example: 50% of $10,000 at $100/share = 50 shares

c) Fixed Amount
    Shares = Fixed Dollar Amount / Entry Price
    Example: $5,000 fixed at $100/share = 50 shares

d) Risk-Based
    Risk Amount = Available Cash * Risk Percentage
    Shares = Risk Amount / (Entry Price * Stop Loss %)

    Example:
        Capital = $10,000
        Risk = 2% ($200)
        Entry = $100
        Stop Loss = 5%
        Risk per share = $100 * 5% = $5
        Shares = $200 / $5 = 40 shares

Code Location: state_machine.py

Notes:
    - Stocks: rounded down to whole shares
    - Crypto: allows fractional shares
    - Minimum 1 share required for entry


--------------------------------------------------------------------------------
3.3 TRANSACTION COSTS
--------------------------------------------------------------------------------

Commission Per Trade:
    Cost = Fixed $ amount per trade (entry + exit)
    Example: $1 per trade = $2 round trip

Commission Percentage:
    Cost = Trade Value * Percentage
    Example: $10,000 trade * 0.1% = $10

Slippage:
    Actual Price = Order Price * (1 + Slippage %)  [for buys]
    Actual Price = Order Price * (1 - Slippage %)  [for sells]

    Example:
        Order to buy at $100, slippage = 0.1%
        Fill price = $100 * 1.001 = $100.10

Code Location: state_machine.py

Notes:
    - Commissions deducted from cash
    - Slippage applied to fill price
    - If costs exceed available cash, position size reduced


--------------------------------------------------------------------------------
3.4 RISK MANAGEMENT (STOP LOSS / TAKE PROFIT)
--------------------------------------------------------------------------------

Stop Loss (Percentage):
    Stop Price = Entry Price * (1 - Stop Loss %)
    Triggered when: Low <= Stop Price

Take Profit (Percentage):
    Target Price = Entry Price * (1 + Take Profit %)
    Triggered when: High >= Target Price

Dynamic Stop Loss:
    Stop Price = Indicator Value (e.g., ATR-based trailing stop)
    Triggered when: Close crosses below indicator

Code Location: state_machine.py

Priority:
    1. Stop Loss checked first
    2. Take Profit checked second
    3. Exit signal checked last

Exit Reasons:
    - "signal": Normal exit condition triggered
    - "stop_loss": Stop loss hit
    - "take_profit": Take profit hit
    - "force_close": End of backtest period

4. INDICATOR WARMUP
================================================================================

--------------------------------------------------------------------------------
4.1 WARMUP PERIOD CONCEPT
--------------------------------------------------------------------------------

Problem:
    Moving averages and oscillators need historical data to initialize.
    First N bars have NaN values until indicator has enough data.

Solution:
    Trim bars where any indicator has NaN values.
    Start backtest from first bar where all indicators are valid.

Example:
    SMA(50) needs 49 prior bars to calculate first value.
    RSI(14) needs 14 prior bars.
    Warmup period = max(49, 14) = 49 bars trimmed.


--------------------------------------------------------------------------------
4.2 WARMUP CALCULATION
--------------------------------------------------------------------------------

Algorithm:
    1. Identify all indicator columns in DataFrame
    2. Find first row where ALL indicators are non-NaN
    3. Trim all rows before that point
    4. Return trimmed DataFrame and count of bars removed

Code Location: indicator_layer.py (trim_warmup_period function)

Report Fields:
    - requested_start_date: User's original start date
    - actual_start_date: First bar after warmup trim
    - warmup_bars_trimmed: Number of bars removed
    - warmup_note: Human-readable explanation

Notes:
    - Minimum 30 bars required after warmup
    - If insufficient data, backtest fails with error message

5. SIGNAL GENERATION
================================================================================

--------------------------------------------------------------------------------
5.1 CONDITION EVALUATION
--------------------------------------------------------------------------------

Operators:
    GT  : left > right
    LT  : left < right
    EQ  : left == right (with tolerance)
    GTE : left >= right
    LTE : left <= right
    CROSSES_ABOVE : left crosses from below to above right
    CROSSES_BELOW : left crosses from above to below right
    IS_RISING : left > left.shift(1)
    IS_FALLING : left < left.shift(1)

Logic Combinators:
    AND : All conditions must be True
    OR  : At least one condition must be True

Code Location: condition_engine.py


--------------------------------------------------------------------------------
5.2 CROSSOVER DETECTION
--------------------------------------------------------------------------------

CROSSES_ABOVE:
    (left_prev <= right_prev) AND (left_curr > right_curr)

CROSSES_BELOW:
    (left_prev >= right_prev) AND (left_curr < right_curr)

Where:
    *_prev = value on previous bar
    *_curr = value on current bar

Notes:
    - First bar always returns False (no previous value)
    - Handles NaN values gracefully (returns False)

6. ATTRIBUTION ANALYSIS
================================================================================

--------------------------------------------------------------------------------
6.1 SIGNAL STRENGTH
--------------------------------------------------------------------------------

Formula:
    Signal Strength = Conditions Met / Total Conditions

Example:
    Entry has 3 conditions, 2 are True
    Signal Strength = 2/3 = 0.67

Bins:
    Strong: >= 0.7
    Medium: 0.3 - 0.7
    Weak:   < 0.3

Code Location: state_machine.py, report_generator.py


--------------------------------------------------------------------------------
6.2 TRADE ALPHA
--------------------------------------------------------------------------------

Formula:
    Trade Alpha (%) = Trade PnL (%) - Market Return During Trade (%)

Where:
    Market Return = (Exit Close - Entry Close) / Entry Close * 100

Example:
    Trade PnL = +15%
    Market moved = +10%
    Trade Alpha = 15 - 10 = +5%

Notes:
    - Positive = trade beat buy-and-hold for that period
    - Negative = would have been better to just hold


--------------------------------------------------------------------------------
6.3 CONDITION FREQUENCY
--------------------------------------------------------------------------------

Tracks how often each condition triggered a trade entry.

Usage:
    - Identify which conditions drive most entries
    - Find underperforming or redundant conditions

Code Location: report_generator.py (generate_attribution_report)

7. ROBUSTNESS ANALYSIS
================================================================================

--------------------------------------------------------------------------------
7.1 PARAMETER SENSITIVITY
--------------------------------------------------------------------------------

Process:
    1. Take baseline strategy parameters
    2. Generate variants by adjusting each param by ±X%
    3. Run backtest for each variant
    4. Compare metrics across variants

Default Variation: ±20%

Example:
    SMA period = 50
    Variants: 40 (-20%), 60 (+20%)

Code Location: robustness/parameter_sensitivity.py


--------------------------------------------------------------------------------
7.2 STABILITY SCORE
--------------------------------------------------------------------------------

Formula:
    Stability Score = 1 - mean(Coefficient of Variation for each metric)

Range: 0.0 to 1.0

Interpretation:
    >= 0.8 : ROBUST (stable across parameter changes)
    0.6-0.8: MODERATE (some sensitivity)
    < 0.6  : FRAGILE (highly sensitive to parameters)

Code Location: robustness/parameter_sensitivity.py


--------------------------------------------------------------------------------
7.3 COEFFICIENT OF VARIATION (CV)
--------------------------------------------------------------------------------

Formula:
    CV = Standard Deviation / |Mean|

Calculated for:
    - total_return_pct
    - sharpe_ratio
    - win_rate

Example:
    Returns across variants: [20%, 25%, 22%, 18%]
    Mean = 21.25%
    Std = 2.99%
    CV = 2.99 / 21.25 = 0.14

Notes:
    - Lower CV = more stable
    - CV > 0.5 considered high variability


================================================================================
8. ASSUMPTIONS & LIMITATIONS
================================================================================

Market Assumptions:
    - Unlimited liquidity (no market impact)
    - Always get filled at expected price (after slippage)
    - No partial fills
    - No overnight gaps affecting stops (intraday not modeled)

Data Assumptions:
    - OHLCV data is accurate and adjusted for splits/dividends
    - No survivorship bias in ticker selection
    - Yahoo Finance data quality accepted as-is

Model Assumptions:
    - Risk-free rate = 0 for Sharpe calculation
    - 252 trading days per year
    - Returns are roughly normally distributed (for Sharpe validity)
    - Transaction costs are symmetric (same for buy/sell)

Limitations:
    - No short selling support
    - Single position at a time (no pyramiding)
    - No margin/leverage
    - No reinvestment of dividends (price returns only)
    - No tax considerations
    - No portfolio-level analysis (single asset only)

See docs/V1_LIMITATIONS.txt for detailed roadmap.
