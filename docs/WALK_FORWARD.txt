WALK-FORWARD VALIDATION

================================================================================
OVERVIEW
================================================================================

Walk-Forward Validation tests whether a strategy performs consistently across
different time periods. It divides historical data into N equal windows and
runs the backtest on each window independently.

KEY INSIGHT:
A strategy that works great in 2020-2021 but fails in 2022-2023 may be
overfit to specific market conditions. Walk-forward validation exposes this.

IMPORTANT DISTINCTION:
- Walk-Forward VALIDATION (implemented): Tests FIXED parameters across windows
- Walk-Forward OPTIMIZATION (not implemented): Re-optimizes parameters per window

We implemented validation because it answers: "Does my strategy work consistently?"
Optimization is a quant-level feature that requires a parameter optimizer.


================================================================================
HOW IT WORKS
================================================================================

1. FETCH DATA
   - Load full OHLCV data for the specified date range

2. COMPUTE INDICATORS ONCE
   - Calculate all indicators on the full dataset
   - This avoids warmup loss per window (key optimization)

3. TRIM WARMUP
   - Remove leading NaN bars from indicator calculation
   - Ensures all windows have valid indicator values

4. DIVIDE INTO WINDOWS
   - Split data into N equal windows by BAR COUNT (not calendar)
   - Equal bar count ensures equal sample sizes per window

5. RUN BACKTEST PER WINDOW
   - Execute strategy on each window independently
   - Collect metrics: return, Sharpe, drawdown, win rate, trade count

6. CALCULATE CONSISTENCY SCORE
   - Use Coefficient of Variation (CV) across windows
   - Lower CV = more consistent = higher score

7. GENERATE ASSESSMENT
   - ROBUST / MODERATE / FRAGILE based on score and profitability

================================================================================
INTERPRETING RESULTS
================================================================================

CONSISTENCY SCORE (0.0 - 1.0):
-----------------------------
The consistency score measures how stable performance is across windows.

Formula: Score = 1.0 - mean(Coefficient of Variation across metrics)

- 0.8 - 1.0:  Highly consistent (metrics vary < 20% across windows)
- 0.6 - 0.8:  Moderately consistent
- 0.0 - 0.6:  Inconsistent (metrics vary wildly)


ASSESSMENT LEVELS:
-----------------
ROBUST:
  - Consistency score >= 0.8
  - At least 80% of windows profitable
  - Interpretation: Strategy works reliably across different time periods
  - Action: Safe to consider for live trading

MODERATE:
  - Consistency score >= 0.6
  - At least 60% of windows profitable
  - Interpretation: Strategy shows some period dependency
  - Action: Investigate underperforming periods, consider regime filters

FRAGILE:
  - Below MODERATE thresholds
  - Interpretation: Strategy is highly period-dependent, may be overfit
  - Action: Do NOT trade live without significant improvements


RISK FLAGS:
----------
Common risk flags and their meaning:

"Strategy was unprofitable in X/Y windows"
  - Some time periods had negative returns
  - Consider what market conditions caused the losses

"X/Y windows had insufficient trades for reliable metrics"
  - Windows with < 10 trades have low statistical significance
  - Metrics from these windows may be misleading

"High variance in performance across time periods"
  - Consistency score < 0.5
  - Strategy may be regime-dependent or overfit

"Significant loss (X%) in period: [dates]"
  - One window had > 10% loss
  - Investigate what happened during this period


SUFFICIENT SAMPLE WINDOWS:
-------------------------
Windows with total_trades >= 10 are considered to have sufficient sample size.
Windows with fewer trades are:
- Still included in the report
- Excluded from consistency score calculation
- Flagged if too many windows lack sufficient trades

================================================================================
BEST PRACTICES
================================================================================

1. USE SUFFICIENT DATA
   - Aim for at least 3 years of data
   - Each window should have 50+ trading days minimum
   - More windows = better validation but smaller sample per window

2. CHOOSE APPROPRIATE WINDOW COUNT
   - Default: 5 windows (good balance)
   - 3 windows: Coarse validation, larger samples
   - 10 windows: Fine-grained but smaller samples per window

3. INTERPRET total_trades
   - Windows with < 10 trades: Low confidence in metrics
   - Windows with 10-19 trades: Moderate confidence
   - Windows with 20+ trades: High confidence

4. INVESTIGATE UNDERPERFORMING WINDOWS
   - What market conditions existed?
   - Was it a trending or range-bound market?
   - High or low volatility?

5. COMBINE WITH PARAMETER SENSITIVITY
   - A strategy can be consistent across time but fragile to parameters
   - Run both analyses for complete picture


================================================================================
TECHNICAL DETAILS
================================================================================

WINDOW GENERATION:
-----------------
Windows are divided by bar count, not calendar dates.

Example: 1000 bars, 5 windows = 200 bars each
  Window 1: bars 0-199
  Window 2: bars 200-399
  Window 3: bars 400-599
  Window 4: bars 600-799
  Window 5: bars 800-999

Remainder bars are distributed to first N windows:
  1003 bars, 5 windows = 201, 201, 201, 200, 200 bars


INDICATOR OPTIMIZATION:
----------------------
Indicators are computed ONCE on the full dataset, then sliced.

Why this matters:
- A 50-period SMA needs 50 bars of warmup
- With 5 windows, naive approach loses 50 bars × 5 = 250 bars
- Our approach loses only 50 bars total

This is achieved by:
1. compute_indicators(full_df)
2. trim_warmup_period(full_df)
3. generate_windows(trimmed_df)
4. For each window: slice the pre-computed df


CONSISTENCY SCORE FORMULA:
-------------------------
For each metric (return, Sharpe, win_rate):
  1. Collect values from all valid windows
  2. Calculate mean and standard deviation
  3. CV = std_dev / |mean|  (capped at 1.0)

Overall score = 1.0 - mean(all CVs)


================================================================================
LIMITATIONS
================================================================================

1. FIXED PARAMETERS ONLY
   Does not re-optimize parameters per window. For that, you need
   Walk-Forward Optimization (not implemented - quant-level feature).

2. NO REGIME AWARENESS
   Treats all time periods equally. Future enhancement: weight windows
   by market regime similarity to current conditions.

3. EQUAL WINDOW SIZES
   All windows have same bar count. Future enhancement: allow custom
   window boundaries or regime-based splits.

4. NO ROLLING WINDOWS
   Windows are non-overlapping. Future enhancement: add option for
   rolling/overlapping windows.
