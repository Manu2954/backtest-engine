✅ Features Extracted (all real-time computable, no lookahead):
  1. volatility - rolling std of log returns
  2. trend_strength - R² from OLS regression (0-1)
  3. trend_slope - OLS slope (directional signal)
  4. price_vs_sma50 - (price - SMA50) / SMA50
  5. returns_autocorr - lag-1 autocorr (mean reversion signal)
  6. rsi_level - RSI at entry (optional, if strategy uses it)
  7. atr_pct - ATR as % of price (optional)

WHAT'S MISSING (v2 - FUTURE)
-----------------------------

❌ Multi-Feature Combinations
  Current:
    - "Trade when trend_slope > 0.001" (single feature)
    - "Trade when volatility ∈ [0.02, 0.03]" (single feature)

  Needed:
    - "Trade when vol ∈ [0.015, 0.025] AND trend_strength > 0.6" (combination)
    - "Trade when vol ∈ [0.02, 0.03] AND autocorr < -0.2 AND slope > 0" (3-way)

Why not implemented yet:
  - Single-feature addresses 80% of the use case
  - Combinations require decision trees or combinatorial search
  - Risk of overfitting with sparse data in multi-dimensional bins
  - Harder to interpret
  - Want to validate single-feature approach first with users

THE GAP: SINGLE vs MULTI-FEATURE
---------------------------------

What we have (single-feature):
  ✅ Fast to compute
  ✅ Easy to interpret ("vol too high" = clear)
  ✅ Production-ready (add as simple filters)
  ✅ Low overfitting risk
  ❌ Misses interaction effects ("vol matters more when trend weak")

What quant firms use (multi-feature):
  ✅ Finds interaction effects
  ✅ More precise conditions
  ✅ Higher win rates on combinations
  ❌ Complex (decision trees, grid search)
  ❌ Needs more trades (sparse data in 3D)
  ❌ Overfitting risk
  ❌ Harder to explain to users

FUTURE OPTIONS
--------------

Option 1: Ship single-feature as-is
  - Let users manually combine ("filter on vol AND trend")
  - Iterate based on real usage feedback
  - Safest approach, validates concept first

Option 2: Add full multi-feature now
  - Use sklearn decision tree to find best splits
  - Report top 5 feature combinations with metrics
  - Most sophisticated but highest risk

Option 3: Hybrid (2-feature pairs only)
  - Test all pairwise combinations (7 features = 21 pairs)
  - Report top 3 pairs: "vol ∈ [X,Y] AND trend > Z"
  - Middle ground: more powerful than single, less risky than full tree
  - Add optional parameter: find_combinations=True (default False)
