SECTION 1: COUNTER-TRADE BUGS (NEW)
================================================================================
Previously documented: CT-001 through CT-004

CT-NEW-005 | HIGH | Counter-trade ignores leverage configuration
--------------------------------------------------------------------------------
Location: state_machine.py:1343-1350, 1097-1113
Issue: Counter-trades inherit global leverage param. For 10x leverage strategies,
counter-trades also use 10x, compounding losses in reversal scenarios.
Fix: Store leverage separately in counter_trade_pending dict, allow override.

CT-NEW-006 | MEDIUM | Counter-trade TP uses PnL% which includes costs
--------------------------------------------------------------------------------
Location: state_machine.py:1241, 1275
Issue: Counter TP = abs(pnl_pct) * multiplier, but pnl_pct already includes
commission/slippage from losing trade. Counter-trade needs 3%+ price move
when TP set to 3% because it pays additional costs.
Fix: Use pure price move: abs((exit_price - entry_price) / entry_price * 100)

CT-NEW-007 | MEDIUM | Counter-trade race condition with opposite pending entry
--------------------------------------------------------------------------------
Location: state_machine.py:1343, 1356-1358, 1378-1380
Issue: Counter-trade can be armed but blocked by previously-armed opposite
position, leaking state that never executes.
Fix: Check for opposite pending_entry before arming counter-trade.

CT-NEW-008 | LOW | Counter-trade exit_rule_states captured at wrong bar
--------------------------------------------------------------------------------
Location: state_machine.py:1344, 1346, 1124-1125
Issue: entry_bar_idx set to ARM bar, not FILL bar. Exit rules capture refs
from wrong bar.
Fix: Same as CT-004 - update entry_bar_idx after fill.

CT-NEW-009 | CRITICAL | SHORT counter-trade with leverage uses wrong proceeds formula
--------------------------------------------------------------------------------
Location: state_machine.py:422-435, 436-451, 560, 606, 1251-1282
Issue: Leveraged SHORT exits use LONG proceeds formula. Margin and PnL
calculation is incorrect for leveraged shorts.
Fix: Add direction-aware branch in leveraged exit path.

CT-NEW-010 | MEDIUM | Counter-trade with risk_based sizing uses wrong stop
--------------------------------------------------------------------------------
Location: state_machine.py:1097-1113, 309-318, 534-544
Issue: risk_based sizing calculates position from ATR at counter-trade entry
bar, not original trade's stop. Position size varies wildly.
Fix: Force fixed_amount or percent_capital for counter-trades.

ATTR-001 | CRITICAL | Market return uses signal bars, not fill bars
--------------------------------------------------------------------------------
Location: state_machine.py:186-206, 238-241, 467-486
Issue: entry_bar_idx and exit_bar_idx are SIGNAL bars, but fills happen at
NEXT bar's open. Alpha = trade_return - market_return compares mismatched
periods (execution prices vs signal prices).
Fix: Pass fill bar indices to calculate_market_return.

ATTR-002 | HIGH | Market return uses close prices, fills use open prices
--------------------------------------------------------------------------------
Location: strength_calculator.py:189-190, state_machine.py:1097-1113, 1128-1145
Issue: calculate_market_return uses close-to-close. Trades fill at open.
Overnight gaps included in trade PnL but excluded from market return.
Fix: Use open-to-open for market return, or document the discrepancy.

ATTR-003 | MEDIUM | SL/TP exits have conceptually flawed market return
--------------------------------------------------------------------------------
Location: state_machine.py:787-820, strength_calculator.py:189-190
Issue: Trade exits at stop price, but market return uses close. Alpha
compares stop execution against close movement.
Fix: Use actual exit price for market return calculation.

ATTR-004 | MEDIUM | Liquidation trades have no attribution data
--------------------------------------------------------------------------------
Location: state_machine.py:671-698
Issue: Liquidation creates TradeRecord directly without calling
_create_trade_record_with_attribution.
Fix: Add attribution capture for liquidation exits.

ATTR-005 | LOW | Force close trades have no exit attribution
--------------------------------------------------------------------------------
Location: state_machine.py:1439-1461
Issue: Last bar force-close calls _execute_exit without exit_attribution_data.
Fix: Capture exit attribution for force_close trades.

ATTR-006 | LOW | Attribution captured at signal bar, not validated at fill
--------------------------------------------------------------------------------
Location: state_machine.py:1355-1363, 1379-1384, 1096-1126
Issue: Indicator values may change between signal and fill. Attribution
records signal state, not execution state.
Fix: Document this as intended behavior or capture at fill.

ATTR-007 | LOW | No signal_strength for exit signals
--------------------------------------------------------------------------------
Location: state_machine.py:152-183, 243-246
Issue: Entry has signal_strength, exit does not. Asymmetric analysis.
Fix: Add exit_signal_strength field.

ATTR-008 | LOW | Dynamic TP not distinguished in exit_reason
--------------------------------------------------------------------------------
Location: state_machine.py:1114-1118, 804-820
Issue: Both static and dynamic TP exits use 'take_profit' reason.
Fix: Use 'dynamic_take_profit' for dynamic TP exits.

SECTION 5: POSITION SIZING BUGS
================================================================================

SIZE-001 | HIGH | total_capital uses cash, not equity
--------------------------------------------------------------------------------
Location: state_machine.py:546, 301, 320
Issue: percent_capital and risk_based modes use cash only, not total equity.
After first trade, sizing shrinks because position value not counted.
Fix: total_capital = cash + position_mtm for these modes.

SIZE-002 | MEDIUM | Commission not reserved before sizing
--------------------------------------------------------------------------------
Location: state_machine.py:547-556, 566-568
Issue: Size calculated, then commission causes overflow, triggers fallback.
Inefficient and edge cases may fail.
Fix: Reserve commission upfront in sizing calculation.

SIZE-003 | CRITICAL | Leverage multiplies shares AFTER risk_based sizing
--------------------------------------------------------------------------------
Location: state_machine.py:559-561, 308-326
Issue: risk_based calculates shares for X risk, then leverage multiplies,
making actual risk X * leverage. Completely breaks risk management.
Fix: _calculate_position_size must know leverage and size for margin, not
multiply afterward.

SIZE-004 | MEDIUM | risk_based doesn't account for commission
--------------------------------------------------------------------------------
Location: state_machine.py:308-326, 323-325
Issue: Same as SIZE-002 but specific to risk_based mode.
Fix: Account for commission in max affordable shares calculation.

SIZE-005 | HIGH | full_capital doesn't reserve for commission
--------------------------------------------------------------------------------
Location: state_machine.py:297-299, 578-580
Issue: Uses ALL cash, then commission must come from... where? Always
triggers fallback recalculation.
Fix: amount_to_invest = cash - estimated_commission.

SIZE-006 | HIGH | Leverage commission formula wrong in recalculation
--------------------------------------------------------------------------------
Location: state_machine.py:591-592
Issue: price * (1.0 + leverage * commission_pct / 100.0) is WRONG.
Commission on notional, not multiplied by leverage.
Correct: price * (1/leverage + commission_pct/100).
Fix: Rewrite commission calculation formula.

SIZE-007 | LOW | Integer truncation may loop without progress
--------------------------------------------------------------------------------
Location: state_machine.py:596, 332, 598-600
Issue: Recalculation yields same truncated int, no progress made.
Fix: Add logging for silent size rejection.

SIZE-008 | MEDIUM | max_position_size not implemented
--------------------------------------------------------------------------------
Location: state_machine.py:284-333, 918-952
Issue: CLAUDE.md mentions max position size limits, but no such parameter
exists in run_backtest().
Fix: Add max_position_size parameter with enforcement.

SECTION 7: DATA LAYER BUGS
================================================================================

DATA-001 | HIGH | Timezone inconsistency between providers
--------------------------------------------------------------------------------
Location: yfinance_provider.py:110-111, binance_provider.py:200-206,
         data_layer.py:245-246
Issue: yfinance returns naive UTC, Binance converts UTC→local→naive.
Same timestamp = different date index.
Fix: Standardize all providers to UTC before stripping timezone.

DATA-002 | MEDIUM | Partial/incomplete bar included in data
--------------------------------------------------------------------------------
Location: binance_provider.py:120-125, data_layer.py:276-278, 325-328
Issue: Current incomplete bar included. Training on partial data = bias.
Fix: Filter out bars where timestamp > now - resolution.

DATA-003 | MEDIUM | Gap detection threshold too lenient (min 1 bar)
--------------------------------------------------------------------------------
Location: data_layer.py:586-591
Issue: Single bar passing cache check allows severely incomplete data.
Fix: Require minimum 10-20% of expected bars or consecutive date coverage.

DATA-004 | LOW | Cache invalidation race condition
--------------------------------------------------------------------------------
Location: data_layer.py:544, 562-565
Issue: Redis deleted before DB fetch. Race can re-populate stale data.
Fix: Delete Redis AFTER successful DB fetch.

DATA-005 | HIGH | Date boundary double-addition for Binance
--------------------------------------------------------------------------------
Location: data_layer.py:325-328, binance_provider.py:120-125
Issue: data_layer adds 1 day to end_date, Binance also adds 1 day.
Result: 2 days over-fetch.
Fix: Remove duplication - only one layer should adjust end date.

DATA-006 | LOW | Provider failover documentation mismatch
--------------------------------------------------------------------------------
Location: data_layer.py:625-646, CLAUDE.md
Issue: CLAUDE.md mentions failover, but no failover logic exists.
Fix: Update documentation or implement failover.

DATA-007 | CRITICAL | Binance provider uses FUTURES API, not spot
--------------------------------------------------------------------------------
Location: binance_provider.py:17, data_layer.py:152
Issue: URL is fapi.binance.com (futures), not api.binance.com (spot).
Futures prices include funding, can diverge significantly from spot.
Users expecting spot data get futures data.
Fix: Change to spot API URL or add explicit api_type parameter.
