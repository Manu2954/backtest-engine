- Realistic fill simulation (entry/exit at next bar's open - prevents lookahead bias)
- Position state machine: NO_POSITION → PENDING_ENTRY → IN_POSITION → PENDING_EXIT
- Asset classes: STOCK (integer shares), CRYPTO (fractional shares)

**Technical Indicators** (11 via pandas-ta):

**Condition Operators** (9):
- Comparisons: GT, LT, EQ, GTE, LTE
- Crossovers: CROSSES_ABOVE, CROSSES_BELOW
- Trends: IS_RISING, IS_FALLING

**Operand Types** (4):
- INDICATOR: Technical indicator aliases
- OHLCV: Price/volume data
- SCALAR: Constant numeric values
- LOOKBACK: Historical values (e.g., "rsi_14:-3" = RSI 3 bars ago)

**Position Sizing** (4 modes):
- full_capital: Invest entire cash balance
- percent_capital: Fixed percentage (e.g., 10%)
- fixed_amount: Fixed dollar amount
- risk_based: Size based on risk % and stop distance

**Risk Management**:
- Static stop loss (percentage-based)
- Static take profit (percentage-based)
- Dynamic stop loss (indicator-based trailing stops)
- Commission modeling (per-trade + percentage)
- Slippage simulation

**Data Providers** (Pluggable):
- YahooFinance: stocks/crypto, daily to 1min resolution
- Binance: crypto, multiple resolutions, IST timezone support

**Performance Metrics**:
- Returns: total return %, CAGR, Sharpe ratio
- Risk: max drawdown, Calmar ratio, longest drawdown
- Trade stats: win rate, profit factor, avg win/loss
- Buy-and-hold benchmark comparison

### ✅ Phase 1B: Empirical Binning (100% Complete)

**Purpose**: Data-driven validation of which indicator ranges correlate with profitable trades

**Replaces**: Original Phase 1B plan (5 indicator-specific calculators with arbitrary thresholds)

**Why**: Senior engineer feedback identified flaws in original approach:
- Arbitrary thresholds (RSI 30/70) are subjective curve-fitting
- No validation method - can't prove assumptions
- Combinatorial explosion (5 calculators × params)

**How It Works**:
1. Bin each indicator's entry values by quintiles (5 bins)
2. Calculate avg P&L, win rate per bin
3. Compute trade-level Spearman correlation (indicator value vs P&L)
4. Statistical significance via p-values

**Example Output**:
```json
{
  "rsi_14": {
    "bins": [
      {"range": [10, 30], "count": 30, "avg_pnl": 250.0, "win_rate": 0.67},
      {"range": [30, 45], "count": 25, "avg_pnl": 150.0, "win_rate": 0.60},
      ...
    ],
    "correlation": -0.72,  // Strong negative (low RSI = high P&L)
    "p_value": 0.001,      // Highly significant
    "sample_size": 100
  },
  "summary": {
    "analyzed_indicators": 3,
    "significant_indicators": 1,  // p < 0.05
    "skipped_indicators": ["ema_cross"]  // Crossover-only
  }
}
```

**Requirements**:
- Minimum 50 trades (not 20 - per senior feedback)
- Trade-level Spearman correlation (not bin-level)
- Crossover indicators explicitly skipped with warning

**Status**: Fully integrated, 20 tests passing, documented in backend/docs/EMPIRICAL_BINNING.txt

### ✅ Phase 2A: Parameter Sensitivity Analysis (100% Complete)

**Purpose**: Identify fragile vs robust strategies by testing parameter stability

**How It Works**:
1. Vary each numeric indicator parameter by ±variation_pct (default ±20%)
2. Run baseline backtest + all variant backtests in parallel via Celery
3. Calculate stability score using Coefficient of Variation across metrics
4. Classify strategy robustness level

**Robustness Classification**:
- **ROBUST** (score ≥ 0.8): Metrics vary < 20%, safe to deploy
- **MODERATE** (score 0.6-0.8): Metrics vary 20-40%, use with caution
- **FRAGILE** (score < 0.6): Metrics vary > 40%, suggests overfitting

**Example Output**:
```json
{
  "baseline": {
    "strategy_id": "uuid",
    "params": {"rsi_14": {"period": 14}, "sma_50": {"period": 50}},
    "metrics": {"total_return_pct": 25.5, "sharpe_ratio": 1.8, "win_rate": 62.0}
  },
  "variants": [
    {
      "variant_label": "rsi_14.period: 14 → 11 (-20%)",
      "metrics": {"total_return_pct": 22.1, "sharpe_ratio": 1.5, "win_rate": 58.0},
      "delta_from_baseline": {"total_return_pct": -3.4, "sharpe_ratio": -0.3}
    },
    // ... more variants
  ],
  "stability_metrics": {
    "overall_stability_score": 0.85,
    "per_metric_cv": {"total_return_pct": 0.12, "sharpe_ratio": 0.15}
  },
  "assessment": {
    "robustness_level": "ROBUST",
    "risk_flags": [],
    "recommendation": "Safe to deploy with confidence"
  }
}
```

## Strategic Direction: "Truth Engine"

**Vision**: Strategy validation platform that distinguishes real edge from overfitting

**Core Value Proposition**: "Backtest engines lie. We tell the truth."

**Key Insight**: This isn't about running backtests faster or having more indicators. It's about determining if backtests are **TRUSTWORTHY** before risking capital.

**Problem**: Traders are deceived by backtests (overfitting, regime bias, unrealistic execution assumptions)

**Solution**: Tools that validate whether strategies will work, not just how they performed historically

**Competitive Position**:
- Tier 1 (TradingView/Backtrader): Basic backtesting ($0-50/mo)
- Tier 2 (QuantConnect): Good execution modeling ($50-200/mo)

## Quick Start

### Setup
```bash
# Infrastructure
docker-compose up -d  # PostgreSQL + Redis

# Backend
cd backend
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
alembic upgrade head
uvicorn app.main:app --reload --port 8000

# Celery Worker (separate terminal)
celery -A app.celery_app.celery_app worker --loglevel=info

# Frontend (separate terminal)
cd frontend
npm install
npm run dev  # http://localhost:5173
```

### Run Tests
```bash
cd backend
pytest tests/  # All tests
pytest tests/unit/  # Unit only
pytest tests/integration/  # Integration only
```

### Environment Variables
```env
DATABASE_URL=postgresql+asyncpg://backtest:backtest@localhost:5432/backtest
REDIS_URL=redis://localhost:6379/0
CELERY_BROKER_URL=redis://localhost:6379/1
CELERY_BACKEND_URL=redis://localhost:6379/2
OHLCV_CACHE_TTL_SECONDS=86400
```
